Before the first lab

Setup, and the computer basics around R

Every lab runs on your own laptop, in R and RStudio. The first half of this page is a checklist to work through at home before Tuesday of week 1. The second half is a reference for the moments when the computer gets in the way instead of R: a download you cannot find, a zip that will not open, a file R says does not exist, a key you cannot type.

Before Tuesday of week 1

1

Two minutes

Check your laptop

A Windows laptop (Windows 10 or 11) or a Mac works. A Chromebook, an iPad, or a work laptop on which you are not allowed to install software will not run RStudio. If that is your situation, send us a message on Canvas before week 1 and we will find a solution together.

2

About twenty minutes

Install R, then RStudio

R is the program that runs your code. RStudio is the program you work in; it starts R for you. Both are free. Install R first.

  • Windows
  • macOS
  1. Go to cran.r-project.org, click Download R for Windows, then base, then the download link at the top.
  2. Open the downloaded .exe file and click through, keeping every default. If Windows asks whether the app may make changes to your device, click Yes.
  3. Go to posit.co/download/rstudio-desktop and download RStudio Desktop for Windows. Open it and keep every default.
  4. Open RStudio from the Start menu: press Win, type RStudio, press Enter.
  1. Check which chip your Mac has: the Apple menu (top left) > About This Mac. It says either Chip: Apple M… or Processor: … Intel.
  2. Go to cran.r-project.org and click Download R for macOS. With an Apple chip, take the installer whose name ends in arm64.pkg; with Intel, the one ending in x86_64.pkg. The wrong one installs fine and then causes trouble later, so check twice.
  3. Open the .pkg file and click through.
  4. Go to posit.co/download/rstudio-desktop and download RStudio Desktop for macOS. Open the .dmg file and drag the RStudio icon into the Applications folder in that window. Then eject the RStudio disk in the Finder sidebar.
  5. Open RStudio from Applications, or press Cmd + Space, type RStudio, press Enter. If macOS asks whether you are sure you want to open an app downloaded from the internet, click Open.

Done when the console (the pane at the bottom left) shows a line starting with R version 4., and typing 1 + 1 there and pressing Enter prints [1] 2.

3

Two minutes

Change three settings in RStudio

Open Tools > Global Options.

  • Under General, untick Restore .RData into workspace at startup, and set Save workspace to .RData on exit to Never. Every session then starts empty, so your code has to work from top to bottom on its own, which is what happens when someone else runs it.
  • Under Code, tick Use native pipe operator, |>. The shortcut Ctrl + Shift + M (Cmd + Shift + M on a Mac) then types the pipe the labs use.

Click OK.

4

Ten to twenty minutes, on a good connection

Install the course packages

Packages add functions to R. This installs every package the labs use, so no lab has to start with a download. Copy the command (the button at the top right of the box does that) into the RStudio console and press Enter:

install.packages(c("tidyverse", "tidytext", "sotu", "textstem",
                   "tidymodels", "textrecipes", "glmnet", "discrim",
                   "naivebayes", "LiblineaR", "stopwords", "tidyllm",
                   "rmarkdown"))

A lot of red text scrolls past. That is normal: R prints its progress in red. It is finished when the > prompt is back at the bottom of the console.

If R asks Do you want to install from sources the packages which need compilation?, type no and press Enter. If it asks whether to use a personal library, answer yes both times. What these questions mean.

Five minutes · this is also a rehearsal of every lab

Make a course folder and run the setup check

Make one folder for the course, for example cadc inside Documents. Every lab comes as a zip file, and every zip gets extracted into this folder.

  1. Download the setup check (button below) and extract it into your course folder. On Windows: right-click the zip > Extract All. On a Mac: double-click it, then move the folder that appears into your course folder. More on zip files.
  2. In the extracted folder, open setup-check.qmd in RStudio. If a double-click opens it in another program, use File > Open File in RStudio instead.
  3. Click the green ▶ at the top right of the grey code box.

The check looks at your R version, your packages and the folder you are working in, and says [ok], [note] or [fix] for each. A [fix] line also says what to do. Done when nothing says [fix], and clicking Render at the top of the editor opens a web page with the same report.

If you get stuck, bring the check’s output to the first lab, or paste it into your message when you ask for help. It tells us most of what we need to know.

In the first labs, most time is lost on things around R: a file in the wrong folder, a zip that was never extracted, or a key nobody can find. If you hesitate on any of these, read the section it links to.

Downloads

Your browser saves files to the Downloads folder unless you told it otherwise. To find the file you just downloaded, click the download icon (an arrow) at the top right of the browser, then Show in folder (Windows) or the magnifying glass (Mac). On Windows, Ctrl + J opens that list in most browsers.

  • Downloading the same file twice gives week01-lab-a (1).zip. Delete the old one, or you will not know which one you extracted.
  • Downloads is a place files pass through. Do not work in it: move what you need into your course folder.

Zip files

A zip file packs several files into one, so a lab can be one download. Before you can use the files, they have to be extracted.

  • Windows
  • macOS

Double-clicking a zip shows what is inside, but extracts nothing. Code you open from there cannot find its data, and whatever you save is lost (the explainer under Paths shows why). Instead:

  1. Right-click the zip > Extract All…
  2. Click Browse and choose your course folder, then Extract.

It worked when you see an ordinary folder, without a zipper on its icon.

Double-click the zip in Finder. It is extracted into a folder of the same name, next to the zip. Move that folder into your course folder.

Safari extracts zips by itself after downloading, so you may find a folder in Downloads rather than a zip. That folder is what you need.

File extensions

The last part of a file name, after the dot, says what kind of file it is: .csv is a table, .qmd a Quarto document, .zip a packed folder. Windows and macOS hide it by default, which makes ess-news.csv and ess-news.zip look alike. Make them visible:

  • Windows
  • macOS

In File Explorer, open View > Show and tick File name extensions (Windows 11). On Windows 10, open the View tab and tick File name extensions.

In Finder, open Finder > Settings > Advanced and tick Show all filename extensions.

Two traps this prevents:

  • Renaming without seeing the extension turns data into data.csv.csv, and R cannot find data.csv.
  • Saving a .csv from Excel. Opening one in Excel to look at it is fine. Saving it is not: on a Dutch or German computer Excel writes semicolons instead of commas and decimal commas instead of points, and it can change dates and long numbers. Look at data in RStudio instead (View(ess), or click the table in the Environment pane).

If double-clicking a .qmd opens the wrong program, open it from RStudio with File > Open File. To make RStudio the default: on Windows, right-click the file > Open with > Choose another app > RStudio, Always; on a Mac, select the file, press Cmd + I, choose RStudio under Open with and click Change All.

Where your files live

Keep one folder for the course, for example Documents/cadc, and extract every lab into it. After two weeks it looks like this:

cadc/
├── setup-check/
├── week01-lab-a/
│   ├── week01-lab-a-part1.qmd
│   ├── week01-lab-a-part2.qmd
│   ├── ess-news.csv
│   └── guns-polls.csv
├── week01-lab-b/
└── week02-lab-a/
  • Cloud folders. On many laptops Documents and Desktop are synced to OneDrive (Windows) or iCloud Drive (Mac). That is fine, with one setting: synced files can live only in the cloud until you open them, and R cannot always read those. Right-click your course folder and choose Always keep on this device (OneDrive) or Keep Downloaded (iCloud).
  • Names. File and folder names without spaces and special characters save typing and mistakes: week01_notes.qmd, not Week 1 notes (final!).qmd.

Paths

A path is the address of a file: the route through the folders to get to it. Click through the six steps below; it is the one idea on this page that most “file not found” errors come down to.

Copying the path of a file:

  • Windows
  • macOS

Select the file in File Explorer and press Ctrl + Shift + C (Windows 11), or hold Shift, right-click the file and choose Copy as path. You get something like:

"C:\Users\sam\Documents\cadc\week01-lab-a\ess-news.csv"

R reads a \ as the start of a special character, so pasting that gives Error: '\U' used without hex digits in character string. Replace every \ with /:

read_csv("C:/Users/sam/Documents/cadc/week01-lab-a/ess-news.csv")

Select the file in Finder and press Option + Cmd + C. Or right-click it, hold Option, and choose Copy … as Pathname. You get something like:

/Users/sam/Documents/cadc/week01-lab-a/ess-news.csv

In the labs you will rarely need a full path, and you should not hand one in: a line with C:/Users/sam/... in it runs on Sam’s laptop and nowhere else. Keep the data next to the .qmd and use the file name alone. A data file in a subfolder is data/ess-news.csv; .. means one folder up.

R and your folders

R looks for files in one folder at a time, the working directory.

  • In a .qmd file, the working directory is the folder the .qmd is in, both when you run a chunk and when you click Render.
  • In the console, it is a separate folder, usually your home folder. A line you type in the console therefore looks somewhere else than the same line in a chunk.
  • To check: getwd() prints the working directory, list.files() the files in it.
  • Avoid setwd("C:/Users/..."). It works on one computer only, and inside a .qmd it lasts for one chunk. Move the files instead.

Try it once. Open setup-check.qmd, add a chunk at the end (Ctrl + Alt + I, on a Mac Cmd + Option + I), and run:

writeLines("Hello from R", "hello.txt")

Find hello.txt in File Explorer or Finder, and in RStudio’s Files pane at the bottom right. Then type the same line into the console, press Enter, and find out where that copy went (getwd() tells you). Delete both files afterwards.

A shortcut that prevents typos: type read_csv(" and press Tab. RStudio lists the files in the working directory; type the first letters and press Tab again. If the file is not in the list, R will not find it either.

Installing software

What you might see, and what to do.

R asks Do you want to install from sources the packages which need compilation? (Yes/no/cancel). Answer no. The newest version of a package is sometimes not yet prepared (“compiled”) for your system. Yes means your computer has to compile it, which needs extra tools you probably do not have. No gives you the previous, ready-made version, which is fine.

R asks Would you like to use a personal library instead?. Answer yes, and yes again when it offers to create one. Packages then go into a folder of your own.

R warns Rtools is required to build R packages (Windows). Ignore it. You only need Rtools to compile packages, see above.

Error: there is no package called ‘tidytext’. The package is not installed. Run install.packages("tidytext") once.

Error: could not find function “read_csv”. The package is installed but not loaded in this session, or the name has a typo. Run the library(...) line at the top of the file. Installing happens once per computer; library() once per session.

Mac: RStudio is gone after a restart, or there is an RStudio disk in the Finder sidebar. You ran it from the download instead of installing it. Drag RStudio into Applications, then eject the disk.

Mac: the setup check says you have the Intel version of R. Download the installer ending in arm64.pkg from CRAN, install it over the old one, restart RStudio and install the course packages again.

Your R is more than a year old. Install the current version the same way as the first time, then run the package line from step 4 again: packages belong to one R version. RStudio updates itself through Help > Check for Updates.

RStudio in five minutes

RStudio has four panes. Top left is the editor, where your .qmd file is open. Bottom left is the console, where R runs things and prints the results. Top right, Environment lists the objects you have made. Bottom right, Files shows the working directory, and Plots and Help appear there too.

A .qmd file mixes text with grey code chunks. Three ways to run code:

  • One line: put the cursor on it and press Ctrl + Enter (Cmd + Enter on a Mac). The cursor moves to the next line, so you can step through a chunk.
  • One chunk: click the green ▶ at its top right.
  • Everything above: the small grey ▼ next to the ▶ runs all chunks before this one. Use it when R says an object does not exist because you skipped a chunk.

Render runs the whole file from the top in a fresh session and makes a web page of it. If a file renders with an error but worked when you ran it chunk by chunk, it depended on something you did in the console.

What the console is telling you:

  • > means R is ready.
  • + means R is waiting for you to finish a command, usually a missing ) or ". Press Esc to start over.
  • A small red stop sign at the top right of the console means R is busy. Wait, or press Esc to interrupt it.

When things behave oddly, restart R (Session > Restart R) and run the file again from the top.

Characters R needs that your keyboard may hide

On a US or UK keyboard, |, ~, {, [ and \ are printed on the keys. On other layouts they sit behind a modifier key:

Character German, Windows German, Mac
| AltGr + < Option + 7
~ AltGr + + Option + N, then Space
{ } AltGr + 7 / 0 Option + 8 / 9
[ ] AltGr + 8 / 9 Option + 5 / 6
\ AltGr + ß Option + Shift + 7

For any other layout: on Windows, open the On-Screen Keyboard (press Win, type it) and hold AltGr to see what appears; on a Mac, turn on Show Input menu in menu bar under System Settings > Keyboard > Text Input, choose Show Keyboard Viewer from that menu, and hold Option.

The US-International trap. Many laptops in the Netherlands use the US-International layout. On it, ", ', `, ~ and ^ wait for the next key to make é or ë, so typing read_csv("ess can give read_csv(ëss. Press Space after the quote to get the quote itself, or switch to the plain US layout (ABC or U.S. on a Mac), which has no such keys.

When something goes wrong

Read the last line of the error first. It usually names the problem:

R says What it usually means
object 'ess' not found The line that makes ess has not run yet in this session, or the name has a typo. Run the chunks above (the grey ▼).
could not find function "..." The package is not loaded: run the library() line. Or a typo.
'ess-news.csv' does not exist in current working directory R is looking in another folder than the file is in. See Paths.
there is no package called '...' Not installed yet. See Installing software.
unexpected symbol, unexpected ')' A typo: often a missing comma or bracket on that line or the one before.
unexpected input Often curly quotes, see below.

Curly quotes. Code copied from a PDF, Word or slides often turns " into “ and ”, which R does not accept. Retype the quotes in RStudio, or copy code from the course website with the copy button at the top right of each code box.

Restart and run again. Session > Restart R, then run the file from the top. Many puzzling errors come from leftovers of an earlier attempt.

Asking for help. Say what you ran, what you expected, and paste the error as text, not a photo of your screen. For a screenshot, use Win + Shift + S or Cmd + Shift + 4, then Space. If it is about installing, add the output of the setup check.
